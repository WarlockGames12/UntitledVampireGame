## Programming Rules to follow:

Variables:
- Private serialized variables: camelCase
- Private normal variables: snake_case
- Public variables: PascalCase
- Keep the names tied to the thing you want to create

Comments:
- Use comments to describe how code work on the regular.
- If something has to be done, which you haven't done yet. use: // TODO: comment

Feature Branches:
- Create an seperate branch to work on your own feature.
- Don't use non serious names for branch names.
- During spaces, use a - in between, for example: `feature-branch`
